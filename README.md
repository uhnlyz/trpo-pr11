# Практическая работа № 11 — Рефакторинг и проверка MVC-магазина

## Результат
Итоговая версия магазина с пространствами имён, автозагрузкой, CSRF-проверкой POST-запросов, экранированием вывода, проверкой входных данных и регрессионными сценариями.

## Запуск
Нужен PHP 8.1 или новее. Из корня репозитория:
```bash
php -S localhost:8000 -t public
```
Откройте http://localhost:8000.

## Проверки
Запуск простых автоматических проверок:
```bash
php tests/check.php
```
Проверка синтаксиса всех PHP-файлов:
```bash
find public src views tests -name '*.php' -print0 | xargs -0 -n1 php -l
```
Маршруты и негативные сценарии перечислены в dataset/route_tests.csv и dataset/security_cases.json. Чек-лист архитектуры — dataset/architecture_checklist.csv.

## Архитектура
- public/index.php — точка входа, запуск сессии, CSRF и автозагрузка.
- src/Core/Router.php — сопоставление HTTP-метода и пути с действием.
- src/Controllers — контроллеры страниц, каталога, корзины и заказа.
- src/Models — Product, Category и OrderData.
- src/Repositories — чтение JSON-данных и сохранение заказов.
- src/Services — операции корзины и проверка формы.
- views — отображение подготовленных данных.

Путь запроса: браузер → public/index.php → Router → Controller → Service/Repository → View → общий layout.

## Безопасность
- Все изменения состояния выполняются POST-запросами.
- POST-запросы проверяют CSRF-токен из сессии.
- Значения, выводимые в HTML, экранируются через htmlspecialchars.
- Email проверяется filter_var, обязательные поля очищаются trim.
- Количество товара должно быть положительным, товар должен существовать.
- Неизвестные маршруты и товары возвращают 404.

## Ограничения
Это учебный проект. JSON-файлы не заменяют транзакционную базу данных; нет учётных записей, реальной оплаты, разграничения прав и промышленной защиты от конкурентной записи. Секреты и реальные персональные данные в репозитории не хранятся.
